Release operations

External destinations have an owner and a cadence.

Samsarix LLC maintains the product-facing destinations in docs/portals.json and the authoritative research references in .github/external-links.json. A successful request shows reachability only; it does not prove service health, safety, or endorsement.

Download the canonical Markdown policy.

Cadence and ownership

  • A read-only GitHub Actions workflow checks the inventory each Monday at 09:17 UTC and supports manual runs.
  • support@samsarix.com owns triage, reviews a failed scheduled run within seven days, and records the resolution in the commit or issue that changes the link.
  • Maintainers run npm run check:links before a prerelease and after changing an external destination or research reference.

Result policy

  • HTTP 2xx and 3xx responses pass.
  • HTTP 401, 403, and 429 responses are recorded as reachable but restricted.
  • Other HTTP 4xx responses are broken and require correction, an archive label, or removal.
  • HTTP 5xx, timeout, DNS, and transport failures are indeterminate and require an owner retry.
  • Initial and redirect destinations must remain on public HTTPS; literal local, link-local, and private IP destinations are rejected before they are followed.

Operational boundary

The workflow never edits catalog status or opens an issue automatically. Scheduled GitHub workflows run from the default branch, and GitHub may disable a public repository's schedule after 60 days without activity. If the check disappears, an owner must re-enable and run it manually.
